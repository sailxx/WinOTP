# Κατασκευή και έγκριση Linux

Στοχεύει το x86_64 Linux , αρχικά το Ubuntu 24.04 και το Fedora με . NET 10 εγγενείς εξαρτήσεις. Το frontend είναι Avalonia. η εφαρμογή Windows WinUI δεν έχει αλλάξει. Το Linux χρησιμοποιεί την ίδια συμπαγή διάταξη, κυανό τόνους και μια σκούρα επιφάνεια ελαφρώς χρωματισμένη από τον τόνο του συστήματος (ουδέτερη εναλλακτική όταν δεν είναι διαθέσιμη): Το Windows Mica Alt και το Segoe UI Variable δεν είναι φορητά. Η Inter είναι ομαδοποιημένη. καμία γραμματοσειρά της Microsoft δεν αναδιανέμεται.

Ο κύριος κωδικός πρόσβασης Linux κρυπτογραφεί το θησαυροφυλάκιο με AES -256- GCM και PBKDF2 - SHA256 (600.000 επαναλήψεις). Απαιτείται κατά την εκκίνηση και δεν μπορεί να ανακτηθεί. Δεδομένα: `$XDG_DATA_HOME/WinOTP` ή `~/.local/share/WinOTP`. Ο κατάλογος του Vault είναι 0700 και τα αρχεία θησαυροφυλακίου που δημιουργήθηκαν πρόσφατα είναι 0600. Οι εγγραφές είναι ατομικές, κλειδώνουν με πρόγραμμα εγγραφής και απορρίπτουν παλιές αναθεωρήσεις. Δεν αποθηκεύονται μυστικά στις προτιμήσεις. Ένα θησαυροφυλάκιο υποστηρίζει έως και 500 λογαριασμούς και 14 MiB σειριακά δεδομένα (έτσι το αντίγραφο ασφαλείας Base64 ταιριάζει στο όριο εισαγωγής των 20 MiB). Οι υπερμεγέθεις αποθηκεύσεις απορρίπτονται πριν από την αντικατάσταση. Μην αντιγράφετε ποτέ αρχεία Windows DPAPI στο Linux: εξάγετε ένα κρυπτογραφημένο με κωδικό πρόσβασης `.winotp` δημιουργία αντιγράφων ασφαλείας στο Windows και εισαγωγή του στο Linux. Διατηρήστε την πηγή μέχρι να επαληθευτεί η αποκατάσταση.

## Τοπική ανάπτυξη

```sh
cd /path/to/WinOTP
dotnet run --project tests/Portable/Portable.csproj -c Release
dotnet run --project src/WinOTP.Linux/WinOTP.Linux.csproj -c Release
```

Για μια απομονωμένη προεπισκόπηση χρησιμοποιώντας μόνο δημόσια διαπιστευτήρια RFC:

```sh
cd /path/to/WinOTP
dotnet run --project src/WinOTP.Linux/WinOTP.Linux.csproj -c Release -- --preview --screenshot "$PWD/assets/screenshots/linux-native.png"
```

## Πακέτα

`.github/workflows/linux.yml` εγκαθιστά τις εξαρτήσεις συσκευασίας, επαληθεύει ένα καρφιτσωμένο appimagetool digest, δημιουργεί deb/rpm/ AppImage , εγκαθιστά και ξεκινά το deb κάτω από το Xvfb, ξεκινά το AppImage χωρίς FUSE και ανεβάζει πακέτα συν στιγμιότυπα οθόνης ως `linux-packages`. Λειτουργεί σε PR και μπορεί να εκτελεστεί χειροκίνητα. δεν δημοσιεύει μια έκδοση. `packaging/linux/build.sh` εκτελείται επίσης τοπικά σε έναν κεντρικό υπολογιστή x86_64 Linux με . NET 10, fpm 1.16.0 , rpm και squashfs-εργαλεία. προμήθεια `APPIMAGETOOL` δείχνει το επαληθευμένο εκτελέσιμο 1.9.1 x86_64. Όλο το περιεχόμενο που δημιουργείται παραμένει κάτω `artifacts/linux`.

Η ροή εργασίας της ετικέτας περιμένει για την έκδοση Linux και Windows και στη συνέχεια προετοιμάζει μια **προσχέδιο** κυκλοφορήσει με το πρόγραμμα εγκατάστασης και τα τρία πακέτα Linux. Το GitHub εμφανίζει αναλύσεις SHA -256 για στοιχεία αποδέσμευσης. Ελέγξτε τα πραγματικά στιγμιότυπα οθόνης Linux και λάβετε την έγκριση του Vlad πριν τα δημοσιεύσετε. Η δημιουργία ετικετών ή η προώθηση αλλαγών δεν αποτελεί μέρος της τοπικής προετοιμασίας.

## Απαιτείται ακόμη αποδοχή

Εγκατάσταση/κατάργηση/αναβάθμιση του deb στο Ubuntu και rpm στο Fedora. δοκιμάστε το AppImage και στα δύο ( FUSE ή `--appimage-extract-and-run`). Επαληθεύστε την πραγματική επιφάνεια εργασίας X11 / Wayland, την κλιμάκωση, το χρονικό όριο λήξης του προχείρου, τους επιλογείς αρχείων, την εισαγωγή QR, το κλείδωμα του κωδικού πρόσβασης, την αποκατάσταση αντιγράφων ασφαλείας Windows και την επιμονή HOTP. Η εγκατάσταση του RPM και η συμπεριφορά του desktop compositor δεν καλύπτονται από την εργασία του Ubuntu CI. Δεν έχει υλοποιηθεί ακόμη καμία ενσωμάτωση δίσκου Linux ή εισαγωγή εικόνας πρόχειρου QR. Η εισαγωγή αρχείων QR και η εισαγωγή URI είναι διαθέσιμες.

`assets/screenshots/linux-ui-preview.png` είναι μια πραγματική απόδοση της διεπαφής Avalonia που φιλοξενείται στο Windows, όχι απόδειξη δοκιμής χρόνου εκτέλεσης Linux. Δεν έχουν κυκλοφορήσει πακέτα με αυτήν την αλλαγή.
