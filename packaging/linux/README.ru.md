# Linux сборка и одобрение

Ориентирован на x86_64 Linux, первоначально Ubuntu 24.04 и Fedora с . NET 10 собственных зависимостей. Интерфейс — Avalonia; Приложение Windows WinUI не изменилось. Linux использует ту же компактную компоновку, голубые акценты и темную поверхность, слегка окрашенную системным акцентом (нейтральный запасной вариант, когда он недоступен): Windows Mica Alt и Segoe UI Variable не являются портативными. Интер в комплекте; ни один шрифт Microsoft не распространяется.

Главный пароль Linux шифрует хранилище с помощью AES-256-GCM и PBKDF2-SHA256 (600 000 итераций). Он необходим при запуске и не может быть восстановлен. Данные: `$XDG_DATA_HOME/WinOTP` или `~/.local/share/WinOTP`. Каталог хранилища — 0700, а вновь созданные файлы хранилища — 0600. Записи выполняются атомарно, с блокировкой записи и отклоняют устаревшие версии. Никакие секреты не хранятся в настройках. Хранилище поддерживает до 500 учетных записей и сериализованные данные размером 14 МБ (поэтому его резервная копия Base64 соответствует пределу импорта в 20 МБ); Сохранения слишком большого размера отклоняются перед заменой. Никогда не копируйте файлы Windows DPAPI в Linux: экспортируйте зашифрованные паролем файлы. `.winotp` сделайте резервную копию на Windows и импортируйте ее на Linux. Сохраняйте исходный код до тех пор, пока не будет проверено восстановление.

## Местное развитие

```sh
cd /path/to/WinOTP
dotnet run --project tests/Portable/Portable.csproj -c Release
dotnet run --project src/WinOTP.Linux/WinOTP.Linux.csproj -c Release
```

Для изолированного предварительного просмотра с использованием только общедоступных учетных данных RFC.:

```sh
cd /path/to/WinOTP
dotnet run --project src/WinOTP.Linux/WinOTP.Linux.csproj -c Release -- --preview --screenshot "$PWD/assets/screenshots/linux-native.png"
```

## Пакеты

`.github/workflows/linux.yml` устанавливает зависимости пакетов, проверяет закрепленный дайджест appimagetool, собирает deb/rpm/AppImage, устанавливает и запускает deb под Xvfb, запускает AppImage без FUSE и загружает пакеты плюс снимки экрана как `linux-packages`. Он работает на PR и может запускаться вручную; он не публикует релиз. `packaging/linux/build.sh` также работает локально на хосте x86_64 Linux с расширением . NET 10, fpm 1.16.0 , об/мин и сквошфс-инструменты; поставлять `APPIMAGETOOL` указывающий на проверенный исполняемый файл 1.9.1 x86_64. Весь созданный контент остается под `artifacts/linux`.

Рабочий процесс тегов ожидает сборки Linux и Windows, а затем подготавливает **черновик** релиз с установщиком и всеми тремя пакетами Linux. GitHub показывает дайджесты SHA -256 для ресурсов выпуска. Просмотрите настоящие скриншоты Linux и получите одобрение Влада перед публикацией. Создание тегов или внесение изменений не является частью локальной подготовки.

## Принятие все еще требуется

Установите/удалите/обновите deb в Ubuntu и rpm в Fedora; протестируйте AppImage на обоих ( FUSE или `--appimage-extract-and-run`). Проверьте фактический рабочий стол X11 / Wayland, масштабирование, тайм-аут буфера обмена, средства выбора файлов, импорт QR, блокировку паролем, восстановление резервной копии Windows и постоянство HOTP. Установка RPM и поведение компоновщика рабочего стола не входят в задание Ubuntu CI. Интеграция лотка Linux или импорт изображения QR из буфера обмена пока не реализованы. Доступен импорт файлов QR и импорт URI.

`assets/screenshots/linux-ui-preview.png` Это реальный рендеринг интерфейса Avalonia, размещенного на Windows, а не доказательство теста времени выполнения Linux. В результате этого изменения не было выпущено ни одного пакета.
